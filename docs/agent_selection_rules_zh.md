# Agent 选人规则（白话版）

状态：**研究设计草稿；尚未实现或验证**。  
来源：会议要求（故事 → 量化 → 验证）、`sharpe_dd` 图表观察（尤其 `fig_cum_pnl_all70_stacked.png`）、外部文献。

目标：从 70 个 agent 里，**只用"当时已经知道"的信息**，选出一组，让组合比"全部等权"更好。  
本文把"看图得到的故事"翻译成可计算的规则。**这些规则都只是待检验的想法，不是已证明的规律。**

## 0. 先把几个词说清楚

### 0.1 基础词


| 词                  | 白话                                             | 我们为什么需要它                          |
| ------------------ | ---------------------------------------------- | --------------------------------- |
| PnL                | 盈亏。数据里是 `cum_ot_pnl` 的逐 bar 增量，疑似美元，但点值与成本尚未确认 | 所有比较都用它；单位确认前只报"PnL 单位"，不宣称真实资本回报 |
| long / short agent | long 靠涨赚钱，下单固定 +4；short 靠跌赚钱，下单固定 −4           | 大跌对 long 是坏事，对 short 是机会，必须分开看    |
| flat               | 当天没下单，仓位为 0，PnL 为 0                            | "没出手"和"出手但没赚"是两回事，要分清             |
| session            | 每天 11:35 到 13:30 这段交易时间                        | 只看这段的盈亏，其余时间全是 0                  |




### 0.2 统计与验证词


| 词                      | 白话                                             | 我们为什么需要它                            |
| ---------------------- | ---------------------------------------------- | ----------------------------------- |
| 等权基准（1/N）              | 70 个 agent 每人一份、什么都不挑。这就是我们要打败的对手              | 如果挑人的组合连"什么都不挑"都赢不了，规则就没价值          |
| 趋势 / 市场状态              | 用过去的价格涨跌判断"现在是涨势、跌势还是不明朗"                      | R1 要判断 agent 在该参与的时候有没有参与           |
| 回撤（drawdown）           | 净值从最高点往下掉了多少。例：累计 PnL 从 1000 掉到 700，回撤 300     | R1 用市场回撤定义"压力日"；R2、R4 用 agent 自己的回撤 |
| Sharpe                 | 平均每天赚多少，除以每天波动多大，再年化。越高越"稳稳地赚"                 | 评价 agent 好坏的基本尺子；但短样本里它很容易虚高        |
| 相关系数（ρ）                | 两个 agent 每天盈亏是否同步。+1 同赚同亏，0 互不相干，−1 你赚我亏       | R6 用它找"复制品"                         |
| 聚类 / 簇                 | 把相关性很高的 agent 分到一堆，一堆就叫一个簇                     | 每簇只留一个，避免重复押注                       |
| 前瞻偏差（look-ahead）       | 选人时偷看了未来。例：2020 年初就用"2020 全年 Sharpe"来选人        | 这是回测里最常见的自欺，全文都要避免                  |
| 样本外（OOS）               | 没参与过规则设计、也没用来调参数的数据                            | 只有它能证明规则真的有预测力                      |
| pseudo-OOS             | 历史数据我们已经看过、并用来想规则，所以历史回测只能叫"伪样本外"              | 诚实标注：真正的 OOS 要等规则冻结后的新数据            |
| percentile rank（百分位名次） | 在同组里排第几，换算成 0 到 1。排第一是 1，垫底是 0                 | 不同规则的单位不同，转成名次才能相加平均                |
| PSR（概率 Sharpe）         | "这个 agent 真实 Sharpe 大于 0"的把握有多大。记录越短、波动越大，把握越低 | R5 的诊断量：报告短记录的高 Sharpe 有多少把握；主规格用记录长度打折，不用它剔除 |
| walk-forward（每年重选）     | 每年年初只用此前的数据选一次人，持有一年，下一年再重选                    | 模拟真实操作，避免用未来选人                      |

## 1. 每天发生什么、哪些信息能用



### 主规格的时间线


| 时间           | 可做什么                                   |
| ------------ | -------------------------------------- |
| 决策日前一交易日结束   | `feature_asof`：市场状态、agent 历史和相关性全部截止这里 |
| 决策日约 11:30   | agent 当天独立决定是否下单；不下单即 flat             |
| 11:35 起      | 可开始观察是否进入 ±4 仓位；11:35–13:30 PnL 只属于结果  |
| 当日 session 内 | 已下单仓位当日平仓；下一交易日重新独立决策                  |
| 持有/标签窗口结束    | `label_end`：只有此时标签才成熟，可供以后训练           |


采用"前一交易日截止"的保守口径。原因：时间戳含义和同日信息是否可得还没确认，这样不会泄漏。

### 必须避免

- 用全样本 Sharpe、终值、最终 maxDD 排序再回测同一段。
- 把 2026 年爆仓、全程"能力边界"等事后描述回填到早期。
- 用未来最低点、当年最终涨跌或尚未结束的交易定义当时的市场状态。
- stacked 图按全样本 Sharpe 排序，只能启发假设，不能直接选人。
- 规则已经看过完整历史，因此现有历史 walk-forward 最多称 **pseudo-OOS**；真正 OOS 需要冻结规则后的新数据或未查看的留出期。



### 每日决策与 flat 的识别

我们看不到 agent 的仓位，只能反推。做法：用当天 PnL 的变化除以价格的变化，反推出仓位是 0 还是 ±4。


\widehat{position}_t=\Delta cumotpnl_t/\Delta price_t,\qquad \Delta price_t\ne0


- 业务定义：每个 live agent 每天只有两种决策——下单并于当日平仓，或不操作（flat）。
- 实证下单仓位为 +4（long agent）或 -4（short agent）。
- `trade_day=1`：当日 session 任一价格变动 bar 可推断出该方向 ±4 仓位；若 session 有价格变化但全程未推断出仓位，则记 `flat_day=1`。
- 只有当整段 session 完全没有价格变化时，trade/flat 才不可识别，该日排除。
- 单根 `bar_pnl=0` 或整日 PnL 恰好为 0 仍不能单独证明 flat；必须看整段 session 的推断仓位。
- 首次确认该 agent 已上线前的日期不纳入每日 trade/flat 统计。

## 2. 六条规则

每条规则对应作者看图时的一个直觉。它们是**待检验特征**，不是已证明的选人规律。  
每条规则的"怎么算"保持原定义不变，只是先用白话说一遍，再给一个数字例子。例子里的数字都是虚构的，只为演示算法。

### R1 在场 / 不在场（Side-aware regime participation）

**图上看到什么**  
大跌时，有些 long agent 没下单，躲过了。但对 short agent 来说，大跌是机会，没参与反而是坏事。所以要分多空，看"该在场时在不在、该躲时躲没躲"。

**一句话判断标准**  
long 应该在涨势里出手、在压力期躲开；short 应该在跌势和压力期出手、在涨势里躲开。

**怎么算**  
先给每个决策日贴一个市场标签。标签只用决策日前已知的价格。白话：看过去约 1 个月、3 个月、12 个月的涨跌方向，三票里多数涨就是 up，多数跌就是 down。

业界怎么定义趋势：最常用的就是"过去 k 个月的收益是正是负"，正就算涨势，负就算跌势。这叫 time-series momentum，Moskowitz–Ooi–Pedersen (2012) 用的是过去 12 个月；AQR 的 Hurst–Ooi–Pedersen (2017) 把 1、3、12 个月三个口径合在一起用，CTA 行业的趋势策略基本也是这几个窗口。另一种常见写法是"价格在不在 200 日均线之上"，本质相同。我们没有发明新东西，只是把 1/3/12 月三个口径各投一票。文献支持的是"方向"，不保证这三个窗口对本 agent 池最合适，所以列入下面的可调口径。


trend_d=\frac{\operatorname{sign}(r_{21})+\operatorname{sign}(r_{63})+\operatorname{sign}(r_{252})}{3}


- `up`：`trend>0`；`down`：`trend<0`；`neutral`：`trend=0`。
- `stress`（压力日）：截至前一日的 252 日滚动回撤，低于训练窗历史 20% 分位。白话：市场比过去大多数时候都更接近"深水区"。
- 只计算 agent 已上线、且整段 session 足以识别 trade/flat 的决策日。

**先用主规格测，结果还行再细化。** 市场标签的口径可以换，但要先把上面这一套跑通，再按登记好的备选去试，不能跑完一堆再挑最好看的那个。已登记的备选：

- 压力日分位：20% 之外另试 10% 和 30%。
- 涨势也用分位定义，和压力日对称：`boom` = 252 日滚动收益高于训练窗历史 80% 分位。这样 long 的 opportunity 就是"市场明显在涨的那两成日子"，一个 long agent 在这些日子里一直没出手，P(trade | boom) 就低，R1 自然低。
- 趋势窗口：1/3/12 月之外另试 200 日均线版本。

备选口径只在外层训练段内比较，结果写进登记表；主规格不因备选更好看而事后改动。

再数 agent 的行为。令 `trade_d=1` 表示当天下单，`trade_d=0` 表示 flat。主分数是两个比例的平均：


R1=\tfrac12\left[P(trade=1\mid opportunity)+P(flat=1\mid adverse)\right]


- long：`opportunity=up`，`adverse=stress`。
- short：`opportunity=down or stress`，`adverse=up`。
- 任一条件少于 20 个已上线、可识别的决策日，则 R1 缺失。

这样改的原因：旧写法"大跌时不持仓一律加分"对 short 是错的。大跌时 short 没参与，可能是错失机会。

例子（long agent）：在 100 个 up 日里出手 70 天，比例 0.7。在 50 个压力日里 40 天没出手，比例 0.8。  
R1 = (0.7 + 0.8) / 2 = 0.75。

例子（short agent）：在 40 个 down 或 stress 日里出手 30 天，比例 0.75。在 60 个 up 日里 30 天没出手，比例 0.5。  
R1 = (0.75 + 0.5) / 2 = 0.625。

**我们自己拍的参数**

- 21 / 63 / 252 日趋势窗：自定，不是论文结论。选它们是因为约等于 1、3、12 个月，文献支持"用过去收益刻画趋势"这个方向，但不支持这几个具体天数，也不保证对本池有效。
- 三票平均、`trend=0` 记为 neutral：自定，不是论文结论。选它是因为最简单、不需要拟合任何东西。
- 压力日 = 回撤处于训练窗历史最差 20%：自定，不是论文结论。20% 大约是"每五天有一天算压力"，样本不会太少。
- 每个条件至少 20 个决策日：自定，不是论文结论。太少则比例不稳；选 20 大约是一个月的交易日。

**还没证明的事**  
"过去在场/躲得好"能否预测下一期，必须样本外验证。

### R2 最近在吐回利润（Recent deterioration）

**图上看到什么**  
有的 agent 前几年很好，但最近一两年持续变差，把历史赚的利润吐回去了。

**一句话判断标准**  
最近一年的表现明显不如以前，且当前离历史高点已经回落很多，就扣分。

**怎么算**  
两个量。第一个比较"最近一年"和"更早的历史"的 Sharpe。第二个看当前回撤占已赚利润的比例。

- `perf_gap = Sharpe(last 252 session days) - Sharpe(prior history)`；prior history 至少 252 日。
- `giveback = current_drawdown / max(gross_profit_to_peak, ε)`，全部截至 `feature_asof`。`gross_profit_to_peak` 是累计盈利到峰值时的总额；ε 是防止除以 0 的极小数。
- 在同 side 横截面内，`R2 = rank(perf_gap) - rank(giveback)`，rank 是百分位名次。
- 最近窗口无足够交易时记 missing，不自动判坏。

例子：某 long agent 最近 252 日 Sharpe 为 0.2，更早历史为 1.4，`perf_gap = -1.2`。累计盈利最高到 2000，当前回撤 800，`giveback = 800/2000 = 0.4`。  
在 45 个 long agent 里，perf_gap 的百分位名次是 0.1（很差），giveback 的名次是 0.9（吐回很多）。  
R2 = 0.1 − 0.9 = −0.8，分很低。

**我们自己拍的参数**

- 最近窗口 252 日、prior history 至少 252 日：自定，不是论文结论。选它是因为约等于一年，足够覆盖各种行情，又不至于太长看不出"最近"。
- ε：自定，只是防止除零，数值不影响排序。
- 两项等权相减：自定，不是论文结论。选它是因为最简单。

**还没证明的事**  
"近期持续恶化"是否比全生涯 Sharpe 更能预测下一期，必须样本外验证；没有文献直接保证。

### R3 神一阵鬼一阵（Activation stability）

**图上看到什么**  
有的 agent 出手忽多忽少：某几周扎堆出手，然后长期不动。

**一句话判断标准**  
每年出手次数越不稳、出手越集中在少数几周，分越低。

**怎么算**  
先数"出手"。`entry` 必须是推断仓位从 0 变成 ±4，不能用 `bar_pnl!=0` 冒充交易。  
然后看两件事。第一，各年出手次数的忽高忽低（变异系数 CV = 标准差 ÷ 均值）。第二，出手是否挤在少数几周（标准化 HHI，下面公式；W 是统计窗口内的总周数，s_w 是第 w 周的出手占全部出手的比例）。


HHI^*=\frac{\sum_w s_w^2-1/W}{1-1/W}


`R3 = -0.5 × [rank(CV) + rank(HHI*)]`。至少 3 个完整历史年且至少 20 个可识别 entry，否则缺失。

> 待确认：现版没有写明 W 的取值范围（全部历史的周数，还是最近窗口的周数）。下面的例子按全部历史 52 周演示。

例子：某 agent 三年出手 4、10、16 次，均值 10，标准差约 4.9，CV ≈ 0.49。  
再看一年 52 周内共 10 次出手：若挤在 2 周（各占 0.5），\sum s_w^2 = 0.5，HHI* ≈ (0.5 − 0.019)/0.981 ≈ 0.49；若分散在 10 个不同周（各占 0.1），\sum s_w^2 = 0.1，HHI* ≈ 0.08。  
若 CV 的名次是 0.8、HHI* 的名次是 0.9：R3 = −0.5 × (0.8 + 0.9) = −0.85。越不稳，分越低。

**我们自己拍的参数**

- 至少 3 个完整年：自定，不是论文结论。选它是因为 CV 至少要几个点才算得出。
- 至少 20 个可识别 entry：自定，不是论文结论。作者观察到中位一年约 10 次，20 次约两年，勉强够看分布。
- 按"周"统计集中度：自定，不是论文结论。周大约对应"一波行情"的长度。
- 两项各占 0.5：自定，不是论文结论。

**还没证明的事**  
CV 和 HHI* 只是描述"神一阵鬼一阵"；它们是否有预测力，必须样本外验证。

### R4 出手很多但不赚钱（Trading efficiency）

**图上看到什么**  
有的 agent 交易很频繁，但累计 PnL 曲线是平的。

**一句话判断标准**  
每次出手赚得少、相对回撤赚得少，就扣分。

**怎么算**  
在同 side、同 `feature_asof` 的横截面内比较两个量：

- `efficiency = cumulative PnL / completed entries`：平均每次出手赚多少。
- `Calmar = historical annualized PnL / maxDD`：每年赚的钱相对最大回撤。白话：赚得值不值得吃这个回撤。
- 每年出手次数、或成本未知时的换手代理，只作诊断，不进分数。

`R4 = 0.5 × [rank(efficiency) + rank(Calmar)]`。

例子：agent A 累计 PnL 为 600 点，完成 30 次出手，`efficiency = 20`；年化 PnL 300，maxDD 600，`Calmar = 0.5`。  
若两者在池内的百分位名次分别是 0.2 和 0.3：R4 = 0.5 × (0.2 + 0.3) = 0.25，分低。  
另一个 agent 只出手 8 次却赚 600，`efficiency = 75`，名次会高得多。

**我们自己拍的参数**

- 两项各占 0.5：自定，不是论文结论。选它是因为最简单。
- 选 efficiency 和 Calmar 这两个指标：自定，不是论文结论。选它们是因为分别回答"每次出手值不值"和"回撤值不值"。

**还没证明的事**  
这些是项目自己的指标，没有文献保证它们能预测下一期，必须样本外验证。

### R5 记录太短要打折（Evidence sufficiency）

**图上看到什么**  
有些 agent 刚上线一两年，Sharpe 就很高，但样本太短不可信。已发现：样本越短，Sharpe 越高（Spearman −0.38）；Top10 Sharpe 里 8 个是 2021 年后才启动的。

**一句话判断标准**  
记录越短，分数越往"中游"拉；记录够长才拿满分。新 agent 不剔除，只是打折。历史长且稳定的 agent 自然得高分。

**怎么算**  
R5 不单独打分，而是给 R1–R4 的综合分乘一个"记录长度折扣"。

- 先按 R1–R4 算出综合分 `score`（同轨百分位名次的平均，0 到 1，0.5 就是中游）。
- 记录长度权重 `w = min(1, n / N0)`。n 是该 agent 截至 `feature_asof` 的已上线 session 日数，N0 = 756 日（约 3 年）。
- `score_final = w × score + (1 − w) × 0.5`。白话：记录越短，越不敢相信它的分，就把它往中游拉；满 3 年后不再打折。
- 可计算门槛（这不是 R5 的打分，只是"有没有数据"）：至少 10 个 completed entry，且 R1 可算；否则本期记 missing，不进池。
- PSR 和 MinTRL（Minimum Track Record Length，即把握达到 95% 至少要多长的记录）照常计算并报告，作为"证据强度"诊断。参考 Sharpe = 0，置信水平 95%，偏度和峰度只用 `feature_asof` 之前的样本。
- "PSR ≥ 95% 才合格"的硬门槛版本作为稳健性对照，不是主规格。
- Sharpe 年化需检查序列相关；不能默认直接乘 \sqrt{252} 就可推断显著性。

例子：一个新 agent 上线 1.5 年（378 日），综合分 0.9。w = 378/756 = 0.5，final = 0.5 × 0.9 + 0.5 × 0.5 = 0.70。  
一个老 agent 上线 6 年，综合分 0.8。w = 1，final = 0.8。  
老 agent 排在前面，但新 agent 仍然在池里，分数够高就能进前 20%。  
另一个新 agent 综合分 0.3，final = 0.5 × 0.3 + 0.5 × 0.5 = 0.40，也被往中间拉。折扣对好坏都往中间拉，不是单方面惩罚新人。

> 待确认：R2 需要至少 2 年记录，R3 需要至少 3 年。原来"R1–R4 至少 3 项可算"的要求会把 2 年以内的新 agent 全部挡在门外，与"新人不剔除"矛盾。本版改成"R1 必须有值，R2–R4 有几项用几项"，缺的项由长度折扣兜底。见第 3 节步骤 4。

**我们自己拍的参数**

- N0 = 3 年：自定，不是论文结论。与 R3 的"至少 3 个完整年"一致，大约够经历一轮涨跌。
- 往 0.5 拉而不是往 0 拉：自定，不是论文结论。往 0 拉等于变相剔除新人，与直觉不符。
- 线性权重：自定，不是论文结论。选它是因为最简单；n/(n+k) 等其他形状作稳健性对照。
- 10 个 completed entry 的可计算门槛：自定，不是论文结论。目的是防止"从没出手"的 agent 因为 PnL 恒为 0 而被误当作有数据。
- 偏度/峰度只用决策前样本：这是防前瞻的硬要求，不是可调参数。

**还没证明的事**  
折扣强度（N0）是否合适，必须样本外验证。折扣只改变分数，不解释"短样本 Sharpe 虚高"是行情原因还是选择偏差，这要等教授回答启动日的含义。

### R6 复制品去重（相关聚类）

**图上看到什么**  
有些 short agent 两两相关 0.9 以上，几乎同赚同亏，不该重复选。

**一句话判断标准**  
同一方向里，相关性很高的 agent 算同一簇，每簇只留规则分最高的一个。

**怎么算**  
先把"相关"换成"距离"：越相关，距离越近。再从近到远把 agent 合并成簇，在某个距离处切断。

- **只在同 side 内**做。只用 `feature_asof` 前的日频 PnL，用**带符号的** \rho（不用 |\rho|）。
- 距离 d_{ij}=\sqrt{(1-\rho_{ij})/2}，average linkage（簇与簇的距离取成员两两距离的平均）。
- 至少 252 个共同日；按 \rho\ge0.7 对应的距离切簇（d\approx0.387）。重叠不足的 agent 单独成簇。
- 每簇取规则分最高者。目的是去掉同质复制品，不是跨边配对。

例子：两个 short agent 的 ρ = 0.93，距离 \sqrt{0.07/2}\approx0.19，小于 0.387，同簇，只留分高的那个。  
另一对 ρ = 0.5，距离 \sqrt{0.25}=0.5，大于 0.387，不同簇，两个都可以入选。

**相关矩阵怎么读、互补要什么**（设计备忘；待与 TA 确认）  
现有 `fig_agent_corr_session_daily` 是 session 日频 PnL 的两两 \rho，有正有负。读图时区分四种情况：


| 现象                                | 白话含义             | 怎么处理                                     |
| --------------------------------- | ---------------- | ---------------------------------------- |
| 同方向 \rho 很高（如 short–short 到 0.9+） | 同一天同赚同亏，是复制品     | 一簇只留一个；除非扣掉对方后仍有稳定的额外收益，否则不问"另一个有没有独特信息" |
| 同方向 \rho 低                        | 两者每天的盈亏各走各的      | 更像互补，可以同时选                               |
| 多空 \rho 很高且为正                     | 多空两边常在同一天一起赚或一起亏 | **不是**"涨跌分工"；先当成同质或异常，不据此配对              |
| 多空 \rho 接近 0 或略负                  | 赚钱的日子错开，或有弱对冲    | 与"一边抓涨、一边抓跌"最一致                          |


**目标是互补，不是"相关高就绑一对"。**

- "市场先大涨再大跌，long 与 short 都抓对了"可以成立，但那是**错开赚钱**：涨日 long 赚、跌日 short 赚。日频 \rho 应偏低或略负；周、月累计则都可以漂亮。
- 这种互补靠分轨选人、50/50 预算、R1，以及"多空合并后的路径是否更稳"来捕捉，而不是靠多空 \rho 高来配对。
- \rho\approx -1 是强对冲（同日你赚我亏），与"轮流抓对方向"不是一回事；主规格暂不把负相关当作同簇或自动配对。
- 大量 flat（PnL=0）会压低或扭曲相关；正式规则应只用可识别的 trade/flat 日或足够共同活跃的日子算 \rho（实现时再钉口径）。

待 TA 确认的问题：同向高相关是否一律每簇留一；跨边是否只做分轨加 R1、不做相关配对；相关是否继续用带符号日频 PnL、阈值是否用 0.7。

**我们自己拍的参数**

- \rho\ge0.7：自定，不是论文结论。0.7 是"明显同步"的常用口语线；图上的复制品在 0.9 以上，所以 0.7 偏保守。
- average linkage：自定，不是论文结论。选它是因为不像"取最近"那样容易把一长串弱相关的 agent 连成一大簇。
- 至少 252 个共同日：自定，不是论文结论。约一年，保证相关系数不是几天巧合。
- "每簇留一个"：自定，不是论文结论。文献支持用相关结构分散风险，但没有说该留几个。

**还没证明的事**  
去重后的组合是否在样本外更稳，必须验证；文献只支持"利用相关结构分散"的方向，不保证对本池有效。

### 明确排除

- 同向 dead-hold 对齐后 gap≡0，只是数据 sanity check。
- 不因胜率高就要求 agent"多交易"；研究只能筛选 agent，不能改变原 agent 的决策逻辑。
- 持仓捕获率在固定 ±4、近乎整段 session 持仓下接近恒等，不作为核心信号。

## 3. 怎么把规则拼成一个组合



### 拼装步骤

1. **分多空两轨。** long 和 short 各自一个池子，互不混比。
2. **可计算门槛。** 至少 10 个 completed entry 且 R1 可算，否则本期不进池。这只看"有没有数据"，不看好坏。
3. **同轨内转成百分位名次。** R1–R4 在各自轨内转为 percentile rank，单位不同的规则才能相加。
4. **打分。** R1 必须有值，R2–R4 有几项用几项；对有值的项取等权平均，得到 `score`。
5. **R5 打折。** `score_final = w × score + (1 − w) × 0.5`，w 是记录长度占 3 年的比例，最高为 1。新 agent 往中游拉，不剔除。
6. **每轨取前 20%。** 按 `score_final` 取最高的前 20%。
7. **同轨去复制品。** 对入选者按 R6 聚类，每簇只留分最高的一个。
8. **轨内等权，多空各占一半。** 组合固定 50% long / 50% short 的 gross budget。若一轨没有人合格，该轨空仓（现金），不借给另一轨。
9. **每年重选一次。** 每年第一个交易日之前，只用此前数据重做第 1–8 步，然后持有一年。

> 待确认：现版把去相关（步骤 7）列在"取前 20%"之后，所以最终入选数会少于合格池的 20%。如果想让最终人数等于 20%，应先去重再取前 20%。这里按现版顺序写，没有改动。

Top 20%、等权打分和 50/50 都是为了便于预先注册而定的主规格，**不是论文推导出的最优值**。

### 要打败的两个对手

1. **全员等权：** 每个时点所有已可用的 agent，每人一份。这是最朴素的对手。
2. **分轨等权（主基准）：** 同样 50% long / 50% short，但每轨内不挑人、全员等权。它和我们的组合唯一的区别就是"有没有挑人"，所以这是最公平的对手。

> 不做“同波动率缩放基准”。把等权路径乘以 \(\sigma_{\text{rules}}/\sigma_{\text{b2}}\) 只是给基准加杠杆，不是独立策略；规则若已在 Sharpe / 总 PnL 上输给主基准，更不必用它来解释“是不是多冒了风险”。

点值、成本、滑点和资本占用未确认前，只报告"PnL 单位组合"，不宣称真实资本回报。

### 候选池（point-in-time universe）

point-in-time 的意思是：每个历史时点，只能从当时已存在的 agent 里选。

- 官方没有提供 agent 的上线/下线日期。临时用"首次识别到下单日"当作上线日的代理；此前不纳入候选池。
- 这有一个无法消除的问题：我们分不清"还没上线"和"已上线但一直没出手"。同时，如果池子里只留下了后来活得好的 agent，会有幸存者偏差（survivorship bias）。这必须写进结论的限制里。
- 进不进候选池只看当时"有没有数据"（第 3 节步骤 2）；不能用"未来是否最终有数据文件"来决定历史候选池。R5 只打折，不决定进池。

## 4. 怎么验证自己没自欺



### 外层：每年重选，pseudo-OOS

- 每年第一个 session 之前重选一次，训练集是此前全部已成熟的数据，持有一年。
- 需要等未来 M 日才能知道结果的标签，要等到 `label_end <= feature_asof` 后才进入训练。白话：结果还没出来的数据，不许拿来学。
- **把各年的 OOS 日 PnL 接成一条连续曲线**，再统一计算 Sharpe、maxDD、Calmar、换手和相对基准的收益。不要对各年 Sharpe 求平均，因为每年只有约 250 天，平均会掩盖年间的亏损。

pseudo-OOS 的意思：历史数据已经被我们看过并用来想规则，所以历史回测只能叫 pseudo-OOS；规则冻结后的新数据才算真 OOS。

### 内层与多重检验

- 主规格先冻结。若一定要选权重或阈值，只在外层的训练段内再做一层 walk-forward。
- **登记所有试过的参数**：窗口、阈值、Top 比例、组合版本。试得越多，碰巧赢的概率越大，必须让读者看到试了多少次。
- 报告 PSR 和 DSR（Deflated Sharpe Ratio，按"试了很多次"和非正态做了修正的 Sharpe 概率）。
- 同时和多个候选比较基准时，用 SPA / Reality Check（专门校正"挑最好那个"的检验），或用 block-bootstrap（成块重抽样，保留日与日之间的关联）做等价检验。
- 稳健性检查不能反过来修改主规格，再宣称"样本外"。



### 失败标准

若规则组合不能同时满足以下条件，则判定没有增量：

- 连续 OOS 路径优于匹配的主基准；
- 优势不是由一两个年份或少数 agent 驱动；
- 风险调整后结果在 block-bootstrap / 多重检验下仍站得住；
- 加入合理成本后不消失。

## 附录 A. 证据等级与文献

正文把每个参数都标成"自定"或"文献支持方向"。这里是完整的证据分级，供查证。


| 等级           | 含义                       | 本文例子                            |
| ------------ | ------------------------ | ------------------------------- |
| **M：已建立方法**  | 文献直接支持统计/验证方法            | 1/N 基准、PSR/DSR、data-snooping 检验 |
| **P：外部经验先验** | 文献支持经济方向，但不证明本 agent 池有效 | 滞后收益刻画趋势、相关聚类分散风险               |
| **H：项目假设**   | 来自本项目读图，必须样本外检验          | 近期恶化、活动集中、高频低效能否预测未来            |
| **D：人为设计**   | 为可执行而预先固定，不等于"有论文证明"     | 再平衡频率、窗口、Top 比例、long/short 预算   |




### 主要外部依据及边界

1. **趋势先验（P）**：Moskowitz, Ooi & Pedersen (2012) 发现多类期货存在 1–12 个月 time-series momentum；Hurst, Ooi & Pedersen (2017) 使用 1/3/12 月趋势组合。
  → 支持"过去自身收益可作为趋势状态"，**不支持任意 20/60 日窗口，也不证明 R1 对本 agent 池有效**。
2. **等权基准（M）**：DeMiguel, Garlappi & Uppal (2009) 显示复杂配置 OOS 经常无法稳定击败 1/N。
  → 支持把等权作为强基准，**不支持 50/50 side budget 本身**。
3. **相关聚类（P/M）**：López de Prado (2016) 的 HRP 支持利用相关/协方差层次结构分散风险。
  → 不自动支持"每簇留一个"或某个 linkage/阈值。
4. **Sharpe 推断（M）**：Lo (2002) 说明序列相关会改变 Sharpe 年化与排名；Bailey & López de Prado (2012) 提出 PSR/Minimum Track Record Length；Bailey & López de Prado (2014) 的 DSR 校正选择偏差和非正态。
  → 用于报告证据强度和稳健性对照；主规格的记录长度折扣是自定设计（D），不是这些论文的结论。
5. **数据窥探（M）**：White (2000)、Hansen (2005)、Bailey et al. (2015)、Harvey–Liu–Zhu (2016) 支持 Reality Check / SPA / PBO 和更严格的多重检验。

**没有直接论文保证、只属于 H 的内容**：近期退化能否预测继续失效、entry CV/HHI、PnL/entry、Calmar 筛选、以及 long/short 的 regime participation 对本池是否有效。
